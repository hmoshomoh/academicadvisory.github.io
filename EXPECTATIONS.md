# EXPECTATIONS.md — build gate

Derived from `Academic Support & Complaints System - MVP Build Spec (1).md`.

Rules for this file (from the spec):

- An item is checked (`- [x]`) **only** when a test passes or the feature was personally walked through. Never because the code merely runs without erroring.
- Phase *N+1* is not started until every item in phase *N* is checked.
- A requirement that cannot be met as scoped stays unchecked with a one-line blocker note underneath — never dropped, never reinterpreted.

Verification legend, appended to each checked item:

- `(test: <name>)` — an automated test asserts it. Run them with `python manage.py test`.
- `(walkthrough)` — driven through the running app by hand and observed.

All 41 tests pass. Every role was clicked through in a browser against a seeded database.

### Notes on judgement calls

Two things exist that the spec does not name outright. Both are implementations of
requirements it does make, not additions to scope:

- **`CourseResult`**, a child of `AcademicRecord`. The spec asks an `AcademicRecord` to
  hold "a semester's courses with credit units and grades"; a child row per course is the
  normal way to store a repeating group.
- **Django's own admin site**, registered for academic records and student–adviser
  assignment. Results have to be entered by someone, and the spec's role table gives that
  to nobody in the app's own views. Django's built-in admin is the stack's own answer, so
  it is wired up rather than a second results-entry UI being built. Saving a record there
  regenerates its recommendations. The complaint workflow deliberately stays in the app's
  own views, and the status log is read-only in the admin.

### Known limitations, stated rather than hidden

- Complaint attachments are stored on the local filesystem, which is ephemeral on most
  PaaS dynos. Uploads will not survive a redeploy without a persistent disk.
- `SECURE_HSTS_SECONDS` is not set, so `manage.py check --deploy` still raises W004. HTTPS
  is inherited from the PaaS per the spec, and HSTS is the one security setting Django's
  own documentation warns is hard to reverse — not a good default for a college project.
